# Phase F — Audio / Sound design (strategy)

Strategy document **before coding** (the Dev's request). It makes the **blacked-out screen mode** (blindness) *playable* by sound and improves the experience for everyone. Offline (PWA, public-school hardware), **GPL-clean** and without depending on large files.

## 0. Principles
- **Procedural synthesis (WebAudio)** as the base: earcons, footsteps, ambience and cues are generated by oscillators/filtered noise → **KB, not MB**, offline, no third-party IP (GPL-clean). Real samples come in only later, **if** there is a free licence.
- **TTS** via the **Web Speech API** (`speechSynthesis`) — native to the browser, offline in Chrome/Edge for installed voices; degrades gracefully if absent.
- **Does not replace captions** (1.4 / GAG): captions stay; audio is a parallel channel. Nothing depends **only** on sound.
- **Builds on what exists:** there is already a **master node** (`_masterGain`, created for hearing loss) and an earcon table (`SFX`). The audio bus hangs off the master.
- ⚠️ **Validate with the blind community** (AudioGames.net, associations, with the games *A Blind Legend* / *The Vale* as reference) before settling timbres and the sonar curve.

## 1. Bus architecture (WebAudio)
```
osc/noise of each sound → gainCategoria[cat] → panner(StereoPanner) → _masterGain → [hearing loss?] → destination
```
- **One gain per CATEGORY** (below). The audio menu controls the **toggle + volume** of each one (WCAG **1.4.2 Audio Control**).
- **Spatialization:** `StereoPannerNode` (left/right by the target's relative position) + **attenuation by distance** (volume) + **pitch/tempo by distance** (closer = higher/faster). It implements the request "only hears very close elements" (cut-off by distance) — the same axis used in the hearing-loss simulation.
- Volumes persisted through `localStorage`.

## 2. Categories (each: toggle + volume bar)
| Category | Content | Synthesis |
|---|---|---|
| **Music** | background track | looping 8-bit melody (oscillators) |
| **Ambience** | water, street conversations, traffic, leaves in the wind, rain | looping filtered-noise layers, positional (water = near the water tank; rain follows the City scenery's cycle) |
| **Interaction w/ environment** | footsteps per surface (**grass/floor/stone/sand**), doors (**wood/iron**), ladder (**wood**)/**wall climbing** | filtered noise + short envelope; timbre per material |
| **Earcons** | jump, coin pickup, damage, power, gate, victory | migrates the current `SFX` table |
| **Other effects** | scares, splashes, etc. | — |
| **TTS** | narration (coins left, event, tutorial) | `speechSynthesis`, pt-BR |
| **Sonar** | interaction button + in the menu | sweep that announces the **nearest coin/target**: direction (pan) + distance (pitch) |
| **Edge guard** | warning on reaching a pit/edge | pulsed alert tone, intensifies on approach |
| **Looping cue / guide** | navigation trail | soft looping tone that points the way/goal (pan+pitch by direction) |
| **Danger / barrier** | pit fall, lava; wall/block | low earcon (danger) / muffled "tock" (barrier) |

## 3. Spatial sound design model ("playing blind")
- Each object of interest (coin, door, ladder, edge, wall, danger) emits **events** that the audio engine translates:
  - **Direction** → `pan` (−1 left … +1 right) from the object↔player x difference.
  - **Distance** → volume (falls with distance; cut-off beyond ~N tiles = "only what is close") and **pitch** (close = high).
  - **Height (y)** → a small timbre bias (lower below, higher above).
- **Edge guard:** a sweep ahead of the player; if the next tile in the direction of movement is empty (a pit), a rising alert plays. It matches the edge protection of Easy/toggle movement.
- **Sonar (button):** press → sweeps the targets in an arc ahead and "pings" the nearest (pan+pitch). Also available in the menu.
- **Looping cue:** a continuous loop that points to the recommended path (next coin/door), so the player follows the direction of the sound.

## 4. Integration with the blacked-out screen mode (blindness)
- In `viz='blind'`, switch on an **"audio game" preset** (all spatial cues + edge guard + sonar + looping cue ON) automatically, since the screen is black.
- Outside blind, everything is optional (good for low vision, ADHD, literacy — and for everyone).

## 5. Implementation steps (incremental, each testable)
- **F1 — Bus + audio menu + earcons.** Gain per category, menu (toggle+volume), migrates `SFX` to earcons. The base of everything.
- **F2 — Footsteps per surface + doors/ladder.** Detection of the material underfoot; timbre per material.
- **F3 — Spatialization + sonar + edge guard.** Pan/distance; sonar on the button; pit alert.
- **F4 — Ambience + looping cue.** Positional ambient layers; audio guide.
- **F5 — TTS.** Narration of events and menu.
- (F6 — real licensed samples, if and when there are any.)

## 6. Conformance
- **WCAG:** 1.4.2 (audio control) ✓ via the menu; 1.2.x (media) — captions already exist; 1.4.7 (low background audio) — ambience always below the earcons; offering **volume per category** covers "no background audio".
- **GAG:** sound cues redundant with the visual (never colour-only/sound-only); independent volumes; a **mono** option (accessibility for single-sided deafness) to be evaluated.

## 7. Decisions (closed with the Dev)
1. ✅ **Procedural synthesis now** (GPL-clean, KB, offline). Licensed samples only later, if any.
2. ✅ **TTS = neural, not robotic** (robotic voices cause auditory/cognitive fatigue → `speechSynthesis`/eSpeak NG are **out**).
   - **Primary: Piper TTS** (quality + speed on the government's Positivo tablets). **Secondary: Kitten TTS** (fast, low-cost). **Option: Kokoro-82M** (superior quality, slow — for games with no speed requirement; never the primary).
   - **Implication:** TTS runs **in the browser** (ONNX Runtime Web/WASM + a model in **MB**) → **loaded on demand** (lazy), not embedded in the base bundle. It weighs on the target hardware → it goes in **step F5** (the last) and is optional.
   - **TTS and Captions are SEPARATE, independent toggles** (there is no fallback from one to the other; each switches on by itself).
3. ✅ **Blind switches on the "audio game" preset automatically** (all spatial cues + sonar + edge guard + guide).
4. ✅ **Sonar = hold "swap power"** (hold; the short tap still swaps the power) **or** the chord **swap + special** together (for those who prefer speed). It avoids firing an unwanted action (throwing an object / interacting with a door/person/switch). It requires detecting *hold vs tap* on the swap.
5. The "audio game" mode = **blind** itself (black screen) with the preset on; outside blind the cues are optional (low vision/ADHD/everyone).
6. **Order:** F1 (bus + menu + earcons) → F2 → F3 → F4 → **F5 (neural TTS, lazy)**.
